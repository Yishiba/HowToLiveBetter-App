# 界面与交互

一句话：**打开就知道先做什么，遇到事随时能查到。**

我们不靠多做功能取胜，而是让用户少做决定。每加一个模块、一层导航、一道问题之前，先问：它帮用户做了哪个决定？答不上来就不加。

## 依据

原书的「性价比极高」有严格定义：不花钱、顺手、不用毅力，并且收益大（`CorpusParser.ratioOf`，成本分为 0 且收益为「大」）。再加证据 A 级，2026-10 的正文里共 81 条，其中只有 5 条带人群标签。

由此得出两个结论：

- 首页放一张这 81 条的清单就够了，不需要推荐流、问卷或分类宫格。原书也说「挑走一两条就算数」。
- 书里唯一的个人维度是人群标签。用多道题问用户「关心什么」，对这批最该先做的建议几乎不起作用，所以只问一句「以下哪些符合你」。

## 结构

两个 Tab，加上几个从 Tab 推进去的页面：

```
清单（首页）          查找
  └ 条目                ├ 搜索结果 ─ 条目
                        ├ 遇到事了 ─ 章节 ─ 条目
                        └ 章节目录 ─ 章节 ─ 条目
右上角齿轮 → 关于与设置（含「我的情况」）
首次启动 → 一页：免责说明 + 「以下哪些符合你」（可跳过）
```

## 清单

- **内容**：核心 81 条（性价比极高且证据 A 级），加上用户从别处「加入清单」的条目。
- **人群过滤**：带人群标签的条目，只有符合「我的情况」时才进清单；没填就不进。查找里不做这个过滤，主动查的东西不藏。
- **分组**：用原书自己的口径，即「换回什么」，不另造分类。分段为：全部 / 活得久（换寿命）/ 少亏钱（换钱）/ 不惹事（换人身自由）/ 省时间（换时间精力）。哪段为空就不显示。
- **打勾**：只有一种状态，「做到了」。不设「想做」这一层，少一个决定。勾选后条目沉到本组底部，显示为划线弱化。
- **进度**：顶部显示「已做到 x / 总数」。
- **用户加入的条目**：放在「我加的」一组，同样可以打勾，长按或在条目页可以移出。
- **持久化**：按条目标题去掉 Markdown 记号后的文字记，不按「第几节第几条」记。上游插入新条目会让条号整体后移，标题比条号稳定；标题被作者改写时，这一条的勾会丢，可以接受。

## 查找

- **搜索框**：输入即出结果，复用现有的多词检索和关键词高亮。结果页带「筛选」按钮，打开现有的 10 组筛选。
- **遇到事了**：一排快捷入口，直接进对应章节。包括急救、被骗了、看病、丢工作、租房、家里老人、怀孕、孩子、亲人去世。
- **章节目录**：34 节按 5 个场景分组，一屏看完，每行显示节名和条数：
  - 身心健康：1、2、16、22、24、28、29、33、34
  - 钱与时间：3、4、5、6、7、15
  - 安全与法律：8、9、11、13、14、21
  - 工作与成长：12、19、23、26、31、32
  - 家庭：10、17、18、20、25、27、30
  - 上游新增的节先归入「其他」，等更新映射表。

## 章节

- 标题、条数、「按性价比从高到低」。
- 导读默认折叠。
- 两个快捷开关：「只看零成本」「只看 A 级」，另有「筛选」按钮。
- 条目卡片列表。

## 条目

- **顶部**：节名 · 第几条，然后是标题。
- **说人话**：放在绿色底的引用块里。
- **三格速览**：要花（零成本时写「几乎没有」，否则写出钱、时间、毅力）、换回（寿命 / 钱 / 时间精力 / 人身自由）、证据（A/B/C，点开看含义）。
- **折叠字段**：成本、收益、备注、来源（显示「n 条文献」）。收益默认展开，它是「为什么值得做」的依据；有争议时备注标红并默认展开；其余默认收起。
- **底部唯一主按钮**：
  - 在清单里（核心条目自动在，其他条目加入后在）：「标记为做到了」，做到后变成「已做到，点一下取消」。
  - 不在清单里：「加入清单」。
  - 用户自己加的条目，下面多一个「移出清单」。
- **右上角**：分享。

## 交叉引用

正文里到处是「见第 8 节第 16 条」「本节第 3 条」「第 12、13 条」「第 8 到 10 条」「见第 9 节」这类指路。它们在条目页的各个字段里，以及展开后的节导读里，都可以点。

- **识别规则**：照网页 `index.html` 的 `XREF_RE` 与 `xrefKeys`。只有能解析到真实条目或节的才变成链接，法条条款号（「第 285 条」）解析不到，会留作普通文字。链接文字和加粗里的不认。
- **点了之后**：
  - 只指向一条或一节，就直接打开，返回键回到原处、原位置。
  - 指向好几条，弹出一个列表，标题是点的那处原文，比如「第 16 节第 1、2 条」，选一条再打开。
  - 网页要先弹预览，是因为跳过去会丢掉阅读位置；App 的返回键会回到原处，不需要这一步。
- **样式**：引用带下划线，外链不带。引用在 App 里跳转，外链打开浏览器，两者要分得开。
- **卡片里不做**：卡片整张可点，里面再放链接容易点错。节导读收起时同理，整张卡是「展开」按钮。

## 卡片

一种卡片到处用：标题（最多两行）、说人话（最多两行）、一行灰色小字。小字是文字而不是彩色徽章。

- 在清单里写「换寿命 · 不要早死」。
- 在章节和搜索里写「性价比极高 · A 级 · 零成本」。
- 有争议时末尾加一个红色的「有争议」。
- 正文更新后新增或改动的条目，标题前有一个小圆点。

## 更新提示

- 联网更新成功后，对比新旧两份正文，按标题找出新增和改动的条目。
- 清单顶部出现一行「正文更新：新增 x 条，改动 y 条」，点开看列表，关掉就不再出现。
- 没有更新时什么都不显示。

## 视觉

- 浅灰底，白卡片，12dp 圆角，0.5dp 细边，不用阴影。
- 品牌色只有一个绿；争议用红，其余信息用灰阶。
- 不用照片和插画，场景只用文字标题。
- 深色模式同一套结构，颜色取反。

## 刻意不做

| 不做 | 原因 |
|---|---|
| 问卷 | 见「依据」 |
| 每日一读、推送 | 回访的理由是清单进度，而不是信息流 |
| 收藏 Tab、我的 Tab | 收藏就是清单，设置收进齿轮 |
| 章节长文 + 页内跳转 | 列表可以扫读；条目单独成页，返回键就够用 |
| 配图 | 版权不明，还会挤占文字 |
